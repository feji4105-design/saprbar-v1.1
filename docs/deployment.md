# Развёртывание статической версии

## Архитектурное решение

Приложение полностью выполняется в браузере: редактор, валидация, чтение и сохранение файлов и линейно-статический solver не обращаются к API. Поэтому отдельный сервер приложений, переменные с секретами, база данных и регистрация не нужны. Контейнер использует nginx только для раздачи production-сборки.

Runtime-образ запускается непривилегированным пользователем, слушает порт `8080`, имеет read-only filesystem, все Linux capabilities удалены. Разрешены только `GET` и `HEAD`; остальные методы получают `405`. Для запросов действует лимит 30 запросов/с на IP с burst 60, ограничены заголовки и таймауты. `/healthz` возвращает `200 ok`. Ошибки уровня 5xx получают локальную русскоязычную страницу без деталей реализации.

Загрузка JSON и CN/LD/MD происходит через браузерный File API и не отправляет файлы nginx. Поэтому `client_max_body_size` не ограничивает размер открываемого проекта и служит защитой от случайных HTTP-тел.

## Запуск на localhost

Требования: Docker Engine 24+ либо актуальный Docker Desktop; Docker Compose v2.

```bash
docker compose build
docker compose up -d
docker compose ps
curl -fsS http://localhost:8080/healthz
```

Сайт доступен по адресу <http://localhost:8080>. Привязка в `docker-compose.yml` выполнена к `127.0.0.1`, поэтому порт не открыт в локальную сеть. Значения без секретов перечислены в `.env.example`; Compose автоматически прочитает локальный `.env`, если его создать.

Логи и остановка:

```bash
docker compose logs --tail=100 web
docker compose down
```

## Выпуск с неизменяемым тегом

Для каждого выпуска назначайте новый тег вместо повторного использования `local`:

```bash
SAPRBAR_IMAGE_TAG=2026-10-01 docker compose build
SAPRBAR_IMAGE_TAG=2026-10-01 docker compose up -d
```

После запуска проверьте `/healthz`, загрузку главной страницы, расчёт встроенного примера, изменение нагрузки и повторный расчёт, скачивание/открытие JSON и печатный preview. Пользовательские проекты хранятся как скачанные JSON-файлы, а не внутри контейнера.

## Откат

Не удаляйте предыдущий локальный образ до завершения smoke-теста нового выпуска. Для отката остановите текущий контейнер и запустите прежний тег без пересборки:

```bash
SAPRBAR_IMAGE_TAG=2026-09-30 docker compose up -d --no-build --force-recreate
curl -fsS http://localhost:8080/healthz
```

Откат приложения не изменяет пользовательские файлы. При будущей смене `schemaVersion` до выпуска должна появиться миграция либо документированное изменение major-версии; текущая версия принимает только `1.0.0`.

## Контроль публичного состава

`.dockerignore` разрешает передать сборщику только manifest/lock-файл, конфигурацию TypeScript/Vite, `index.html`, `src/`, Dockerfile и `deploy/`. В финальный слой копируются только `/app/dist`, nginx-конфигурация и `50x.html`. Исходный ZIP, `legacy-extract/`, EXE/BAT, `primer/`, `docs/`, `examples/`, тестовые исходники вне собранного bundle и `node_modules` в runtime не копируются.

После сборки это можно проверить без запуска приложения:

```bash
docker image history --no-trunc saprbar-web:local
docker run --rm --entrypoint sh saprbar-web:local -c 'find /usr/share/nginx/html -type f -maxdepth 3 -print'
```

В JavaScript bundle закономерно присутствует скомпилированный код приложения, включая solver и встроенный пример: для автономной работы браузера это обязательный runtime, а не публикация исходного архива.

## Требования к внешней площадке

Для публикации вне localhost подходит любой контейнерный или статический хостинг, который предоставляет HTTPS, SPA fallback на `index.html`, корректные MIME-типы, долгий immutable-cache для хешированных `/assets/*` и no-cache для `index.html`. Серверные вычисления и постоянный диск не требуются. Перед такой публикацией от владельца нужны только доменное имя, выбранная площадка/реестр образов и сведения о том, кто завершает TLS; платные ресурсы проект не создаёт.
