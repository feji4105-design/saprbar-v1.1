# Форматы файлов SAPR-BAR 3.0

Эта спецификация — транскрипция `HELP_30R.MSG` и `HELP_30B.MSG`, а не результат догадки по файлам KIPR-Win. Обе справки хранятся в CP866. Примеров входных файлов SAPR-BAR в архиве нет.

## Общие правила и неизвестные свойства

Документация показывает последовательности чисел и массивов, но не задаёт расширения в виде `.cn`/`.ld`/`.md`, правила имён, разделитель полей, допустимый синтаксис комментариев, регистр, формат вещественных чисел или максимальную длину строки. Из встроенных строк EXE видно, что интерфейс выбирает CN/LD/MD и способен создавать шаблоны; это не заменяет образцы.

Индексация в справке математическая, с 1 для строк массивов. Столбец 0 означает первое физическое поле записи, а не наличие фиктивного элемента в тексте. Идентификаторы узлов, стержней и типов в ссылочных полях описаны как «порядковые номера» и практически должны быть 1-based; это подтверждено обозначениями диапазонов `1:NR`, `1:NS`, `1:NC`.

**Размерности не задокументированы.** Ниже приведены только физические смыслы величин. Нельзя предполагать SI, мм-кН или любую другую систему без эталонного проекта/руководства. Все согласованные единицы должны образовывать одну выбранную пользователем систему, но даже это обычное инженерное ожидание, а не явная фраза справки.

## CN — конструкция

### Порядок блоков

```text
NR NS NC ND NM
XR: NR строк × 2 поля
XS: NS строк × 3 поля
XC: NC строк × 10 полей (B) или 11 полей (R)
[SC: документирован как NC строк × 5 полей только в R-варианте]
[XD: ND строк × 3 поля]
[XM: NM строк × 3 поля]
```

Источник: таблица структуры CN в HELP_30B/R. Уверенность высокая. В HELP_30R есть внутренняя неоднозначность SC: размер объявлен `SC[1:NC][1:5]`, но строки индексируются через `ISC`, то есть логически число строк должно соответствовать числу типов сдвига. Отдельного счётчика типов SC нет.

### Заголовок

| Поле | Смысл |
|---|---|
| `NR` | число глобальных узлов |
| `NS` | число стержней |
| `NC` | число типов геометрических/механических характеристик |
| `ND` | число стержней с шарнирами |
| `NM` | число сосредоточенных масс |

Все пять значений — счётчики; точный машинный тип и ограничения не документированы.

### XR — координаты

Каждая из `NR` строк: `X1 X2` — координаты узла `I`. Номер узла определяется позицией строки (1..NR), отдельного ID нет. Размерность длины неизвестна.

### XS — топология

Каждая из `NS` строк: `I J Ig`:

- `I` — номер начального узла;
- `J` — номер конечного узла;
- `Ig=S` — номер строки/типа характеристик XC.

Номер стержня определяется позицией строки (1..NS).

### XC — характеристики типа

Есть два несовместимых по длине варианта записи.

**HELP_30B, 10 полей `XC[S][0:9]`:**

```text
K E Ro aT C1 C2 C3 C4 Sp Sc
```

**HELP_30R, 11 полей `XC[S][0:10]`:**

```text
K E ISC Ro aT C1 C2 C3 C4 Sp Sc
```

Поля:

| Поле | Смысл | Размерность |
|---|---|---|
| `K` | код формы 1..4 | безразмерно |
| `E` | модуль упругости | неизвестна |
| `ISC` | индекс строки характеристик сдвига; только R | 1-based либо 0 как выключатель |
| `Ro` | плотность материала | неизвестна |
| `aT` | коэффициент температурного расширения | неизвестна |
| `C1..C4` | геометрия согласно K | неизвестна |
| `Sp`, `Sc` | допускаемые напряжения при растяжении и сжатии | неизвестна |

Геометрические поля:

| `K` | Сечение | `C1 C2 C3 C4` |
|---:|---|---|
| 1 | произвольное | `A Iz y- y+` |
| 2 | круг с круглым отверстием | `D d 0 0` |
| 3 | прямоугольник с прямоугольным отверстием | `B H b h` |
| 4 | прямоугольник с круглым отверстием | `B H d 0` |

Для `K=1`: A — площадь, Iz — момент инерции, `y-`/`y+` — расстояния до нижнего/верхнего волокна. Справка не поясняет знак; скриншот оригинального препроцессора от 2026-10-22 подтверждает запрет y−≥0 для K=1 (см. уточнение ниже). Допустимость сплошного сечения через нулевое отверстие справкой не пояснена.

### SC — характеристики сдвига, только HELP_30R

Строка `SC[ISC]`:

```text
Ky G By SzStar TauAllow
```

- `Ky` — коэффициент неравномерности касательных напряжений;
- `G` — модуль сдвига;
- `By` — ширина на главной центральной оси; вводится для `K=1`, для остальных задаётся 0;
- `SzStar` — статический момент полусечения относительно главной центральной оси; для `K=1` вводится, для `K=2..4` задаётся 0 и вычисляется программой;
- `TauAllow` — допускаемое касательное напряжение.

Размерности `G`, `By`, `SzStar`, `TauAllow` не указаны. HELP_30R говорит: если **любой** `XC[*].ISC` равен нулю, массив SC не формируется, касательные напряжения и деформации поперечного сдвига не учитываются. Формулировка «любой» необычна: неизвестно, допускается ли смешивать типы с/без сдвига.

### XD — концевые шарниры

Каждая из `ND` строк:

```text
P Kb Ke
```

- `P` — 1-based номер стержня;
- `Kb=1/0` — есть/нет шарнира в начале;
- `Ke=1/0` — есть/нет шарнира в конце.

Если `ND=0`, блок отсутствует. HELP_30R/B в заключительном абзаце содержит опечатку `XF` вместо ожидаемого `XD`; таблица и основной текст однозначно называют массив `XD`.

### XM — сосредоточенные массы

Каждая из `NM` строк:

```text
I Mass MassMomentOfInertia
```

- `I` — 1-based номер узла;
- `Mass` — сосредоточенная масса;
- `MassMomentOfInertia` — момент инерции сосредоточенной массы.

Если `NM=0`, блок отсутствует. Размерности неизвестны.

## LD — нагрузки и кинематические ограничения

### Порядок блоков

```text
NA NQR NQS NT
[NB: NA строк × 7 полей]
[QR: NQR строк × 4 поля]
[QS: NQS строк × 5 полей]
[FT: NT строк × 2 поля]
```

Если соответствующий счётчик равен нулю, блок отсутствует. Источник: HELP_30R/B, §4.2; уверенность высокая.

### NB — закрепления и предписанные перемещения

Строка:

```text
I K1 K2 K3 U V F
```

- `I` — 1-based номер узла;
- `K1`, `K2`, `K3` — 0 свободно, 1 ограничено для компонент вдоль глобальных X1, X2 и поворота вокруг X3;
- `U`, `V`, `F` — предписанные значения двух перемещений и угла поворота.

Не пояснено, должны ли значения для свободных компонент быть нулевыми. Размерности линейных перемещений и угла неизвестны.

### QR — узловые нагрузки

Строка:

```text
I F1 F2 M
```

`I` — номер узла; `F1`, `F2`, `M` — сосредоточенные силы по глобальным направлениям и момент (либо их амплитуды при гармонической нагрузке). Размерности и положительные направления не описаны текстом.

### QS — стержневые нагрузки

Строка:

```text
P qx qy mz T
```

`P` — номер стержня; `qx`, `qy` — погонные нагрузки; `mz` — погонный момент; `T` — температура. Для гармонической задачи силовые поля являются амплитудами. Не установлено, заданы ли `x/y` в локальной системе, является ли `T` абсолютной температурой или приращением, и каков знак.

### FT — временной множитель

Строка:

```text
time F
```

`time` — координата узла временной оси, `F` — значение кусочно-линейной функции `F(t)`. Документация говорит о зависимости **силовых** нагрузок от времени. Правила сортировки, экстраполяции и требования к первой/последней точке неизвестны.

## MD — методические параметры

### Базовый порядок

```text
PZ[1..10]   # 10 чисел
IZ[1..10]   # 10 чисел
[MS[1..NS]] # условно, см. Ireg
```

PZ содержит вещественные параметры, IZ — целочисленные по смыслу; точные текстовые типы и допустимый перенос строк не оговорены. Все неиспользуемые позиции PZ/IZ должны быть заполнены нулями.

Общие позиции:

- `IZ[1]=NP`, управление точностью, стандартно 1; точный смысл не раскрыт;
- `IZ[3]=RI`, учёт инерции вращения сечений в динамике: 0/1;
- `IZ[4]=SD`, учёт деформации сдвига: 0/1, только HELP_30R; в B-варианте позиция 4 равна 0;
- `PZ[10]=Ireg`, режим формирования MS;
- `IZ[10]=NZ`, номер задачи: 1, 4, 5, 7 или 9.

`Ireg`:

- 0 — MS формируется автоматически; пример оставляет блок пустым;
- 1 — пользователь задаёт `NS` значений MS;
- 2 — пользователь задаёт только `MS[1]`, применяемое ко всем стержням.

Точный физический смысл `MS` — число промежуточных узлов стержня. Допустимый диапазон в документации не дан; бинарная строка сообщает только верхнюю проверку 250, но без запуска нельзя гарантировать контекст и нижнюю границу.

### NZ=1 — статика

```text
PZ: EPS q_0 q_k dq 0 0 0 0 g Ireg
IZ: NP  NL  0   0|SD 0 0 0 0 Ng 1
```

`EPS` — относительная точность геометрически нелинейного решения; `NL` — максимум итераций Ньютона (`NL=0` даёт линейную задачу); `q_0`, `q_k`, `dq` — диапазон/шаг параметра нагрузки; `g` — ускорение свободного падения; `Ng` — учёт собственного веса 0/1.

### NZ=4 — гармонический отклик

```text
PZ: 0 w_0 w_k dw 0 0 0 0 0 Ireg
IZ: NP 0 RI 0|SD 0 0 0 0 0 4
```

`w_0`, `w_k`, `dw` — начальная, конечная частоты возбуждения и шаг. Единица частоты неизвестна (обозначение `w` может намекать на угловую частоту, но это не доказательство).

### NZ=5 — собственные колебания

```text
PZ: EPS w_0 w_k dw 0 0 0 0 g Ireg
IZ: NP  NL  RI 0|SD M_0 M_k 0 0 Ng 5
```

`M_0`, `M_k` — начальный/конечный тон. `NL>=0` задаёт решение предварительного НДС; при `NL=-1` вычисляются собственные колебания ненагруженной конструкции и LD игнорируется. Значение и роль диапазона `w_0..w_k` описаны лишь как диапазон параметра частоты.

### NZ=7 — динамика во времени

```text
PZ: dt t_k 0 0 0 0 0 0 0 Ireg
IZ: NP N_put RI 0|SD 0 0 0 0 0 7
```

`dt` — шаг интегрирования по времени; `t_k` — конечное время; `N_put` — число шагов между порциями вывода. Метод интегрирования и начальные условия не описаны.

### NZ=9 — устойчивость

```text
PZ: EPS q_0 q_k dq 0 0 0 0 0 Ireg
IZ: NP  NL  0   0|SD 0 0 0 0 0 9
```

Поля аналогичны задаче 1; `dq` используется при поиске критического значения параметра нагрузки. Алгоритм поиска, точность критического значения и трактовка потери устойчивости не приведены.

## Остальные файлы

Статические строки подтверждают существование CNX/LDX/MDX, KPR, MT, RES, OUT, RS0 и FW, но данных для описания порядка записей и полей нет. Особенно важно: HELP прямо предупреждает, что файлы результатов разных версий SAPR-BAR форматно несовместимы. Их парсер нельзя проектировать по расширению или по данным KIPR-Win.

## Реальный оформленный профиль B

Комплект `GOLOBORO.CN/LD/MD` из папки `Ivanov_1`, сформированный редактором SAPR-BAR 3.0, подтвердил внешний синтаксис: первая строка с DOS-путём, служебные строки с `*`, метки записей `=01`, пустые резервные строки `=NN`, конечные маркеры, CRLF и CP866 для русских надписей. Фактический CN соответствует варианту B `XC[0:9]`.

Импортёр игнорирует подтверждённые служебные строки, снимает метку `=NN` и сохраняет физический номер строки для диагностики. Подлинный комплект `GOLOBORO` разобран как B/SI: 5 узлов, 4 стержня, 4 типа свойств, одна опора и четыре узловые нагрузки; блокирующих возможностей нет, линейный расчёт завершается успешно. Это подтверждает чтение данного профиля, но ещё не подтверждает побайтовый экспорт обратно в DOS-редактор или равенство результатов по бинарному `FW`.

## Реализованный профиль импорта

Веб-приложение реализует консервативный текстовый профиль поверх подтверждённых таблиц HELP_30B/R:

- поддерживаются чистые числовые строки и подтверждённое оформление SAPR-BAR B с путём, `*`-строками, `=NN` и пустыми резервными записями;
- поля разделяются одним или несколькими пробельными символами;
- допускаются обычная экспонента `E` и FORTRAN-подобная `D`;
- комментарии не допускаются;
- вариант B (XC из 10 полей) или R (XC из 11 полей и условный SC) выбирается пользователем;
- система единиц выбирается пользователем: SI либо мм–кН–МПа;
- индексы проверяются как целые 1-based ссылки, число записей должно точно совпадать со счётчиками;
- лишние, недостающие, нечисловые и бесконечные значения отклоняются с указанием файла, строки и поля.

Это соглашение необходимо из-за отсутствия в справке лексической спецификации. Успешный разбор означает только соответствие нашему профилю, а не доказанное чтение файла оригинальной программой.

Импорт в расчётную модель разрешён для линейной статики `NZ=1`, `NL=0`, `SD=0`, `Ng=0`, нулевых предписанных перемещений, узловых нагрузок и постоянных `qx/qy`. Ненулевые `mz`, `T`, временная функция, собственный вес, сдвиг, нелинейность и прочие номера задач фиксируются в отчёте и блокируют расчёт. Массы, плотность, коэффициент температурного расширения, допускаемые напряжения и MS также фиксируются, но при отсутствии активирующего их режима не влияют на поддерживаемую линейную статику.

PDF-скриншоты четырёх расчётов SAPR-BAR 3.0 в `primer/` показывают для линейной задачи `q_0=1`, `q_k=1`, `dq=1` и вывод результата при `q=1`. На этом основании импортёр принимает единственное состояние нагрузки `q_0=q_k=1` при положительном `dq` как коэффициент 1 без масштабирования. Другие диапазоны параметра нагрузки блокируются: их последовательность состояний веб-версия не реализует.

В браузере реализовано прямое текстовое создание и редактирование CN/LD/MD в описанном выше синтетическом профиле. Пользователь может начать с пустого комплекта или валидируемого примера B/R, загрузить существующие тексты, проверить комплект, применить поддерживаемую модель и скачать каждый текст без преобразования. Загруженные и отредактированные тексты сохраняются в современном JSON после применения импорта.

Скачивание вручную введённых текстов само по себе не является экспортом современной графической модели: порядок массивов подтверждён, но текстовый диалект, единицы и проверка чтения оригинальным SAPR-BAR — нет. Скачанный `.CN/.LD/.MD` означает только сохранение текста пользователя, прошедшего или не прошедшего наш parser; совместимость с оригинальной программой по-прежнему не заявляется.


## Генерация из JSON / текущей модели (2026-10-22)
`exportLegacySI` создаёт отдельный числовой профиль B, ASCII с CRLF, в SI
(м, Н, Па, Н·м; погонные нагрузки Н/м). Это обратимый адаптер новой веб-версии,
а не подтверждённый формат записи DOS-редактора. Заголовки/резервные записи
оригинального оформленного профиля не воспроизводятся. Чтение оригиналом не проверено.

Экспортируется ровно одно активное линейное загружение. Ошибочная модель,
несколько загружений или блокирующие причины legacy-импорта отклоняются.
Узлы и элементы сортируются по отображаемым номерам, ссылки разрешаются по ID;
номера legacy — последовательные позиции строк. При пропусках в нумерации
получится перенумерация. Ориентация I/J сохраняется.
Каждому элементу соответствует своя строка XC с K=1 и сохранёнными E/A/Iz/y−/y+.
Геометрия не восстанавливается по названию сечения. Поддерживаются XD, NB, QR, QS.
MD задаёт NZ=1, NL=0, SD=0, Ng=0, q₀=qₖ=dq=1, NP=1, Ireg=0.
Массы отсутствуют в современной расчётной модели и не экспортируются.
Ro, aT, Sp и Sc задаются явно отдельными параметрами экспорта; Sp/Sc вводятся
в МПа и переводятся в Па. Одинаковые введённые значения применяются ко всем материалам. Допускаемые напряжения из
произвольного текста описания не извлекаются. Исходные legacy-тексты не копируются:
нерасчётные поля исходника в этот экспорт не входят. Знаки qx/qy следуют
соглашению веб-модели, подтверждения для оригинала пока нет.

В редакторе CN/LD/MD кнопка «Создать из текущей модели (B, SI)» заменяет
рабочие тексты; затем доступны проверка и скачивание каждого файла.
Команда: `node scripts/export-legacy.mjs input.saprbar.json output-directory NAME8 density-kg-m3 aT-per-K Sp-MPa Sc-MPa`.
NAME8 — 1–8 латинских букв, цифр или подчёркиваний. CLI не перезаписывает
существующие файлы. Числа сохраняются через binary64 round-trip без округления.
Тесты проверяют обратный импорт, независимую осевую аналитику, баланс,
ссылки при обратной нумерации, моменты, погонные нагрузки и шарниры.


### Проверка оригиналом: отклонение Ro=0 (2026-10-22)
Скриншот пользователя показывает отказ препроцессора SAPR-BAR v3.0:
`{XC[1][2]=0.000000e+00} <= 0`. В экспортированном B-профиле
это Ro. Таким образом, нулевую плотность нельзя использовать даже при Ng=0.
Экспорт теперь требует явную положительную плотность в кг/м³;
UI и CLI не подставляют материал или значение по умолчанию.
Одна введённая плотность применяется ко всем материалам, что явно подписано в UI.
Число 2700 в тестах — только тестовое входное значение, не свойство модели пользователя.
Другие требования препроцессора ещё не установлены; прохождение этой проверки
не является доказательством полного чтения комплекта.


### Проверка оригиналом: отклонение aT=0 (2026-10-22)
Следующий скриншот после задания Ro показывает `{XC[1][3]=0.000000e+00} <= 0`.
В генерируемом B-профиле индекс 3 — aT. Экспорт теперь требует явный
положительный aT (1/К); значение по умолчанию не подставляется.
Также вводятся положительные Sp/Sc (МПа), чтобы не подменять отсутствующие
допуски нулями. Требование Sp/Sc — консервативный контракт нового экспортёра,
а не установленная по этому скриншоту проверка препроцессора.

В сохранённом IVANOV_SI.CN (производном от оформленного исходного примера)
Ro=8e3, aT=1.2e-5, Sp=70e6, Sc=120e6. Для пользователя создан отдельный
кандидат `output/legacy-rgr19-aT/RGR19V4.CN/LD/MD`: геометрия/нагрузки из
нового JSON схемы 19, Ro/aT из примера, Sp/Sc из таблицы варианта 4.
Это явно смешанный по источникам профиль для проверки ввода; Ro/aT не
объявляются свойствами чугуна из задания. Подтверждённого полного чтения
комплекта оригиналом пока нет. Прежние файлы не перезаписаны.


### Проверка оригиналом: знак y− для K=1 (2026-10-22)
При загрузке V4FIX оригинал сообщил `{XC[1][6]=1.936492e-02} >= 0`.
Это прямое свидетельство, что в проверенном B-профиле координата нижнего
волокна должна быть отрицательной. Ранее положительное расстояние из
веб-модели ошибочно переносилось без смены знака. Экспорт исправлен:
XC[6]=-section.yMinus; XC[7]=section.yPlus. Внутренняя модель по-прежнему
хранит положительные расстояния. Импорт уже нормализует оба поля через abs.
A, Iz, нагрузки и расчётная математика не меняются. Отдельный численный
тест проверяет знаки и точное восстановление исходных характеристик.
Новый комплект V4SIGN сохраняет параметры MD из предыдущего V4FIX;
исправлена только координата нижнего волокна. Полное чтение оригиналом
по-прежнему требует проверки.

## Проверка V4SIGN результатами оригинала (2026-10-22)
Пользователь предоставил согласованный комплект CN/LD/MD, RS0, CNX/LDX/MDX,
KPR, RES и FW после расчёта в SAPR-BAR 3.0. Для **этого конкретного** числового
B-комплекта подтверждены чтение, создание FW и совпадение исследованных
численных блоков с аналитикой и веб-ядром. MD комплекта содержит EPS=1e-8,
g=9.81 при NL=Ng=0; этот факт нельзя автоматически переносить на MD с
EPS=g=0, формируемый общим экспортёром. Универсальный FW-парсер не добавлен.
Схема перенумерации, смещения и границы доказательств: legacy-v4sign-verification.md.

## Стабилизированный экспорт по подлинному V4SIGN (2026-10-22)
Общий экспортёр теперь формирует MD с EPS=1e-8 и g=9.81, q₀=qₖ=dq=1,
NP=1, NL=SD=Ng=0, NZ=1, Ireg=0 — ровно как в принятом V4SIGN.
aT записывается экспоненциально без ограничения числа значащих цифр;
y− отрицательно, y+ положительно. Положительные Ro/aT/Sp/Sc обязательны.
Перед выдачей готовых файлов автоматически выполняется обратный импорт;
ошибка структуры или блокировка поддерживаемого расчёта не даёт скачать комплект.

Добавлено необязательное поле `Project.legacyExport` схемы 1.0.0:
`{profile:"B-SI-linear-static-v1",basename,density,thermalExpansion,tensionMPa,compressionMPa}`.
Это параметры файлового адаптера, не solver-а. density в кг/м³,
thermalExpansion в 1/К, напряжения в МПа. Одни значения действуют для всех
экспортируемых типов; интерфейс явно подписывает это ограничение.
Никаких свойств по умолчанию или по догадке о марке материала не подставляется.
Имя — 1–8 ASCII букв/цифр/подчёркиваний, DOS-зарезервированные имена отклоняются.

Старые JSON без legacyExport открываются без миграции; для первого экспорта
нужны дополнительные свойства. Новые JSON сохраняют их после успешного
создания комплекта. Неверный профиль, нечисловые/неположительные значения,
переполнение Па и неверное имя блокируют открытие/сохранение таких настроек.
Это обратно совместимое необязательное расширение, major не меняется; тесты
проверяют старый файл, новый round-trip и повреждённые свойства.

Кнопка «Скачать комплект CN/LD/MD в ZIP» создаёт три новых файла с единым
именем из текущей модели; она не архивирует предыдущие тексты редактора.
Ручное редактирование/скачивание каждого текста остаётся отдельной функцией.
После успеха параметры записываются в текущий проект; для внешнего JSON-файла
нужно обычное «Сохранить JSON». Изменение только этих настроек не меняет
расчётный вход и не подменяет результаты. ZIP создаётся локально через fflate
0.8.3, без сетевых вызовов и серверов.

CLI принимает `input.json output-directory [NAME8 [Ro aT SpMPa ScMPa]]`:
если дополнительных свойств нет, берёт legacyExport из JSON; неполный
ручной набор отклоняется. Файлы с существующими именами не перезаписываются.

В `tests/fixtures/saprbar-v4sign-authentic` закреплены подлинные CN/LD/MD/RES/FW.
Регрессионный тест сравнивает все три созданных файла **побайтово**, проверяет
ASCII/CRLF, ZIP, сохранение настроек и совпадение с FW этого эталона.
Проверка подтверждает этот вход и профиль; не является обещанием принятия
оригиналом всех размеров/схем/режимов. Неподдерживаемые analysis/load types,
несколько загружений, блокирующий legacy-импорт и структурные ошибки отклоняются.
